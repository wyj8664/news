# 实时排序：progress-decay-v1

适用领域分类和后续新生成的飞书批次，不修改原始时间、event/progress/doc ID、已发历史和历史日报。

- 进展重要性只用该进展关联的报道。每家独立媒体取最强的一条，网站与本媒体微博不叠加；原文排名、权威程度、关键词、多源确认继续有效。
- 计算实时重要性时，将采集次数归一到1，将采集跨日归一到进展首次日期，避免反复采集和同媒体多稿累计抬分。旧的历史日报分数计算路径不变。
- `t` 是距该进展首次可信报道的小时数，不是最近采集、最近转载或整张事件卡的最新时间。
- `时效系数 = 0.5 + 0.5 × 2 ** (-max(0, t - 1) / 6)`；首小时100%，6小时约78%，12小时约64%，24小时约54%，最低50%。
- 每进展的排序分是其重要性乘时效系数。事件卡取关联进展排序分的最大值，不将老进展的重要性与新进展的时间拼接。
- 同分按最新真实进展时间降序，再按稳定事件/进展ID升序；不用采集时间打破平局。Python和浏览器统一按毫秒计时、排序分保留8位小数。
- 浏览器每分钟、重新回到可见状态时，从原始重要性重算所有分类和全部列表，不能对上一次已衰减分再乘一次。展开详情尽量保留，不增加来源请求。
- 首页仍按原文24小时可见性规则过滤；飞书仍使用自己的已确认时间窗口，包括周一周六00:00起的自然日窗口。衰减不缩短飞书回看范围。
- 飞书出箱一旦生成便冻结顺序，恢复未发分片不重排已发内容；真实发送校验窗口、进展关联和该批生成时的排序分，不用恢复时钟重新计算旧分片的规划分。

`news_ranking.py` 与内嵌 `news_ranking.js` 共用版本参数；快照和网页导出每个进展的原始重要性、首次报道时间、衰减系数及排序分。`Event.score` 保留给原有历史日报路径，不把衰减覆盖写回历史重要性。
