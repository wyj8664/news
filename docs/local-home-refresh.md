# 本地领域分类：持久后台更新

入口：`http://127.0.0.1:8799/` 标题右侧“更新领域分类”。普通浏览器刷新只重新载入页面，不会触发采集。

## 行为

- 点击一次，SQLite 记录任务；独立 LaunchAgent 运行。关闭网页不取消任务，再打开可查看同一任务。服务异常重启会恢复未完成步骤；Mac 休眠、关机或 Docker 不可用时不能采集，不保证5分钟完成。
- 第一阶段：原有11个平台热榜和新浪财经 RSS 使用原采集器批次更新；财联社电报、金十公开首页、界面快报依次更新。随后用微博现有缓存生成第一版分类。
- 第二阶段：请求现有 WeiboX 调度器检查到期的关注账号，不新建第二个采集器。已在运行则等待该轮，未到期则沿用缓存，完成后生成第二版分类。
- 网站日报已恢复原版布局：左侧日期归档、右侧连续排名列表，复用 `daily_digest.render_html` 的原模板/CSS，不使用领域卡片或“前10必看／后40备查”。日期入口为北京时间今天及前6天，每天独立按综合分取最多50个事件，不足不补；只纳入硬科技、大宗、新消费、汽车、新能源、金融、物流，排除社会及其他未归类内容。日报使用原文自然日（00:00至次日00:00，不含右端点），而领域分类首页仍是滚动24小时。历史日报不会在24小时到期后消失，重复刷新也不会清空。
- 两个更新阶段均将共享稳定事件／进展／文章ID合并到私有 `.local-refresh/site-daily-output/` 候选账本，再按日排序生成最近7天的 HTML、Markdown 与精选 JSON；同分看最新事实进展的首次报道时间，不看重新采集时间。首次启用及换日时仅用本地RSS/热榜数据库及已有原文时间核验缓存回填，不额外访问来源、不把抓取日期当作原文日期，无法核实的历史内容留空。旧的更早日期文件保留，不执行额外删除。热点脉络入口移除，旧 `/timeline/` 入口跳转日报。
- 日报排序沿用既有事件综合分：来源权重、热榜名次、持续出现、多源覆盖，加上影响范围／可信度／新颖性／后续变量／接近性五个规则维度，扣除水新闻与合集惩罚；不要求必须上榜，也不按七赛道配额平均分配。这是规则排序，不是人工或大模型逐条审核。网站日报不读取飞书已发送历史；飞书仍单独按既定批次窗口和进展去重发送。
- 页面检测到新一版生成时间后自动重载一次，保留已选领域。来源详情区显示实际采集时间；失败不把本次尝试时间当成成功更新时间。
- 同时只运行一个任务。重复点击、多个浏览器以及原定时脚本提交均加入同一队列；上一轮结束后10分钟内不再新开任务。
- 公共批次、各快讯来源最短间隔10分钟；失败尝试也计入冷却。微博沿用数据库当前参数：单账号最短3600秒、轮间3600秒、账号间30～60秒，不因按钮绕过。
- 微博429停止本轮、至少退避一小时；验证码、登录/权限及其他访问异常暂停采集，需人工确认后在管理后台恢复。不自动破解或重试验证码、不切换身份绕过限制。
- 金十及界面只取公开可访问内容，VIP/PLUS/登录受限内容不抓；原文24小时过滤与同事件聚类保持原规则。来源出现“部分更新”不代表抓全了24小时。
- 公众号仍停采；不触发飞书发送。不修改已有留存策略，不执行月度清理。

线上 Pages 尚未连接此本机后台：刷新控制接口明确返回503不可用，不会显示采集成功。本轮没有发布线上网站。

## 文件与启动

- `tools/refresh_service.py`：HTTP控制入口和持久工作线程，固定监听127.0.0.1:8801。
- `tools/refresh_runner.py`：固定工作流；不接受浏览器传入命令、路径、来源URL或凭证。
- `.local-refresh/jobs.sqlite3`：任务、阶段、来源进度与冷却记录；不在output中，不部署到网站。
- `.local-refresh/worker.log`：私有采集诊断日志，不通过网页返回。
- `config/refresh_policy.json`：任务和公共来源冷却、微博最长等待时间（1200秒）。微博实际频率仍以WeiboX为准。
- 飞书发送强制等待：定时提交会在 `scheduled_refreshes` 表绑定批次与任务；微博阶段健康完成（或按限频确认无到期账号）后记录 `weibo-verified`，最终发布保存私有快照及内容哈希。发送任务最多等待1800秒，不消费第一阶段页面；微博异常或不完整时本批不发。此门槛不影响网页分阶段更新，也不会让网页按钮直接触发发群。
- `tools/com.newshot.refresh-service.plist.example`：已安装到本机LaunchAgents，同登录用户运行。需要保持本地预览、刷新后台及Docker可运行。
- `tools/refresh_local_hotlists.sh`：保留原来的周末自动跳过规则，改为只提交同一队列。手动按钮允许用户在周末主动更新。

手动检查后台（不采集）：

```sh
curl --noproxy '*' http://127.0.0.1:8799/api/refresh/status
launchctl print gui/$(id -u)/com.newshot.refresh-service
```

接口不允许跨域写入；POST校验同源Origin、JSON空对象和临时nonce。Worker仅本地8799端口转发到固定后台地址，API不返回微博密码、Cookie或令牌。

## 验证

`tools/test_refresh_jobs.py`覆盖并发去重、任务恢复、冷却保留、两阶段顺序、失败缓存、真实采集时间与Host/Origin/nonce校验。

`tools/test_refresh_worker.mjs`覆盖线上不可用、跨站拒绝、固定代理目标。

`tools/check_home_refresh_ui.py`使用离线模拟任务验证关闭重开、两次阶段发布、领域保留、错误提示与手机布局，不发起真实采集。

WeiboX本地的`local/test_refresh_guard.py`验证同一调度器复用、未到期不触发和访问风险停止。
