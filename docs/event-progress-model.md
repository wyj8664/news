# 领域分类：事件—进展—文章三层模型

## 口径与页面

- `eventid` 表示具体事件，不是公司名、行业名或宽泛话题。
- `progressid` 表示事件中的一个事实进展：披露、回应、下架、召回、立案、处罚等。重复转述不产生新进展；明确不同的回应、金额修订、获批或实施等保留独立节点。
- `docid` 表示来源文章。重复采集同一文章不新增 doc；媒体之间的文章均保留。一篇明确包含多个事实的文章可关联多个 progress，所以各节点文章数之和可能大于事件的唯一文章数。

领域分类默认仍是一事件一行。单文章、单进展不增加复杂展开区域；多进展或多文章时显示进展数、最新进展和可展开的节点/来源。行业分类仍只使用已配置的八个领域，不改变来源权限、采集频率或军事/境外社会新闻的边界。

24小时资格仍按各文章已核实的原文发布时间过滤，采集/转载不会改写原文时间。节点另外记录首次已知报道时间，新增覆盖不重置此时间；这不等于声称已获知事实的精确发生时刻。旧来源过期时，只移除该来源的展示，保留仍有合格文章的节点及其 ID。事件注册记录的生命周期不受页面24小时窗口限制。

## 稳定身份和私有存储

生产生成器使用私有 SQLite：`.local-refresh/events-output.sqlite3`，不在对外发布的 `output/` 目录内，权限为0600。备份/迁移站点时应一并备份此数据库，不能删掉数据库后承诺随机分配的 event/progress ID 还能相同。

文章 ID 使用媒体身份加规范化原文链接，链接无法唯一识别时优先使用上游原生记录 ID，最后才使用标题/原文时间降级。event/progress ID 首次分配后持久保存，不随代表标题、报道数量或页面排序重算。两个已存在的重复分组被可靠合并时，保留较早建立的身份，旧身份保存为别名，可从 `source-pool/home-events.json` 的 `id_aliases` 解析；不是静默丢弃旧 ID。

首次切换会从旧的“成员集合 hash”模型建立新的身份登记。旧版快照已另行备份用于对照，不把不稳定的旧 hash 当作新长期身份。

表结构：`events`、`progresses`、`docs`，以及 `event_docs`、`progress_docs`、候选索引 `blocks`、可解释归属 `decisions`、注册表维护信息 `registry_meta`。外键及关系表唯一键防止悬空关联和重复绑定；更新在 SQLite 事务中提交，异常回滚。

GitHub 工作流已增加对此私有数据库的缓存。缓存是跨运行恢复手段，不是独立备份或强持久云数据库；没有恢复到状态库的冷启动会建立新身份。

## 如何控制计算量

1. 只处理进入首页候选池、原文时间已核实的文章；不对历史全库逐篇运行模型。
2. 同一 doc 内容未变化时，直接读取既有 event/progress 关联，不重复提取或匹配。
3. 用主体和具体四字片段建立 SQLite 候选索引，优先查询较稀疏的片段，最多取40篇候选，每个事件最多比较4个代表报道。
4. 一般候选限于文章发布时间附近45天，长期 ID 与关系保留；明确同一 doc 的更新不受此候选检索期限影响。超长期、缺少共同具体线索的回访报道可能保守地另建事件。
5. 特征缓存按月清理45天外的派生标题/指纹和倒排索引，保留身份、原文链接、归属和进展摘要。不删除原始来源文件，不改变原有来源数据清理策略。

没有逐篇付费大模型调用，没有新增模型/API依赖。所有候选内容可有一个轻量单例事件记录，但只有符合关注领域且仍在时效内的内容才展示卡片；“有记录”不等于“每篇都展开复杂卡片”。

## 匹配与边界

匹配采用标题多视图、有限来源摘要证据、主体/具体对象/动作信息和受约束的分组修复。微博前置话题与【标题】分离，保留原文，匹配及展示使用派生核心标题。宽泛或宣传 hashtag 不能单独构成事件身份。

不同明确主体、合作对象、产品、超标问题、型号、季度和已明确的地震时间冲突优先阻断合并；同一公司或动作相同不构成充分条件。桥接文章只有在候选分组代表也能相互匹配时才允许合并，避免单链传递吞并话题。

节点识别以明确标题事实为主，不把正文背景中每一次历史动作都当作新进展。截断内容没有提供具体回应时，只作为已有回应的待补充覆盖，不凭空编造新的回应事实。不同明确回应事实不合并。来源网站的抒情标题，若被同媒体事实型微博准确引用，可以作为该节点的辅助报道，而不是另造空泛进展。

### 数字及财报事实归一化（2026-10-18）

匹配使用独立的派生事实值，不改写原文：通过 Decimal 统一尾随零、千位逗号、全角数字、正负号、区间和等值金额单位。例如 `104.20%` 与 `104.2%`、`5000万元` 与 `0.5亿元` 等价；人民币与美元、百分比与百分点、正数与负数仍不等价。型号和版本号不按金额处理。

财报节点同时比较指标、报告年/期间、预告/快报/正式披露/修正、增减方向、同比/环比和盈亏。归母、扣非、合并利润、营收和利润率不得混同；累计前三季度不等于单独第三季度。仅在来源首段明确支持同一期间时，才补充省略的年份或净利润口径，不从后文背景借用另一季度。未披露的字段不凭空补全。

升级保留原有身份和首次报道时间：重新解释旧标题的数字（包括早期漏记的负号），在受影响事件内修复重复节点，较早节点存续、其他 ID 留作别名。飞书历史通过别名识别旧回执，不能因修复去重重新发送。同轮待处理的指纹先统一升级，避免混用新旧特征。原生来源电头不算公司主体，微博无冒号的回购标题也提取明确主体，防止金额单位统一后把不同公司的模板公告合并。

这是保守的规则/文本特征实现，不是覆盖所有中文语义的模型，仍可能留有漏合并。应通过真实案例回放和归属日志迭代，不以事件数量下降本身当作正确率。

## 验证与重建

### 2026-10-22 消费品安全事件归并

注册库派生指纹升级至 v8。对有明确品牌、具体产品和质量风险证据的报道，以同一安全事件归并零售商下架、品牌召回、会员短信、检测披露及退款回应；品牌从已采集报道中提取，不把零售商与所有供应商品牌设成全局同义词。仅有品牌名、商品名或宣传话题不足以合并。相同品牌/产品的证据日期须在3天内，明确不同品牌、产品、型号、批次或污染问题优先阻断；缺失证据也不得桥接已明确冲突的两组。

进展按披露、下架、召回、退款、调查、处罚等事实动作区分；无实质信息的“回应下架”、会员短信和重复转述不再新增节点。明确不同批次、范围、数量、罚款金额、回应立场或计划/完成阶段仍保留。完全一致的截断标题只能辅助已有的已证实动作，不能借用相似话题生成新事实。“曾被整改”等历史背景保留在来源/展开信息中，不作为新进展抬升排序或进入飞书待发池。

旧事件和重复进展通过别名并入较早身份，文章和首次报道时间不删除、不重置；飞书已发回执继续通过别名解析，避免修复后重发。退款等明确的产品安全回应归新消费，不因行业词缺失退回社会。规则是本地有界提取与候选匹配，没有新增付费模型调用或采集请求。
