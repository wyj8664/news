# 2026-10-20 去重规则上线

本次只发布网站与云端构建规则，不执行飞书发送，不改发送时间或真实发送历史。

## 规则范围

- `event_registry` 指纹版本 v5：同一进展的多来源转述合并，真实的新数值、阶段、政策修订保留独立节点；稳定 ID 与旧 ID 别名继续使用。
- 核心事实区分增资额、收购主体/标的、声明断言、行情合约与报价，不因补充增幅等辅助信息另建重复进展。
- 同一出口管制公告的发布、条款摘录和无新增措施的官方答记者问合并；编号、对象、主体或明确日期冲突不合并。公告的代表链接优先原文。
- 较短摘要不能清除已核实的结构化事实；云端首次恢复时保留公开快照中的事实依据，避免冷启动后重复出现。
- 分类按新闻意图修正；投票、纯栏目标题、匿名荐股引流等不进入选题。基金/ETF/LOF交易仍优先归金融。
- `briefing_shared` 保留大宗行情展示归并规则，期货/现货的原始价格、进展身份和来源不被改写。本次网站部署不运行该模块的飞书发送流程。

## 发布方式

使用原 `cloudflare-pages.yml`、原 Pages 项目 `newshot` 和原域名 `newshot-5jq.pages.dev`。

先在私有临时目录以本地已采集缓存、SQLite 副本离线重建页面；生产文件和飞书历史保持只读。`public_site_bundle.py` 只打包公开白名单页面及来源数据，拒绝数据库、凭证、发送历史和任意调试目录。

将通过验收的公开包保存为 `data/site-public-seed.tar.gz`，同步核心规则源文件后，以 `deploy_snapshot=true` 发布，跳过新一轮采集。后续原两小时自动更新继续从新源代码构建，不回退到旧去重规则。无需增加采集频率或新增部署项目。
