# NEWSHOT 线上刷新

线上仍为 https://newshot-5jq.pages.dev/ 。刷新控制接口由同源 Pages Worker 接收，只接受固定的“更新领域分类”指令。

## 安全边界

- 查看新闻公开；启动刷新需管理员口令，8小时 HttpOnly / Secure / SameSite=Strict Cookie，写入另校验 Origin 和会话 nonce。认证凭据不进入 URL、localStorage、公开仓库或日志。
- 管理员口令保存在本机 `.local-refresh/online/管理员刷新口令.txt`；代理令牌单独保存为0600的 `agent.json`。云端保存两个口令/令牌的 SHA256 以及单独会话签名密钥，使用 GitHub Secrets 配置 Pages Secrets。
- 本机代理仅主动出站 HTTPS 到固定站点，没有隧道，没有开放8801、微博后台或任何本机端口。浏览器无法传入命令、来源、URL或飞书批次。
- 代理经固定本机入口加入原有 SQLite 队列，复用公共来源10分钟、任务结束后10分钟及 WeiboX 自身账号频率/退避规则；重复请求不会增加并发采集。未到期来源用缓存，不绕过登录/VIP限制。
- 不导入或调用飞书发送程序；本次网页刷新与发送授权分离，原有定时发送安排不由网页控制。

## 持久性与阶段发布

1. Cloudflare KV 保存单槽刷新请求，多次点击按10分钟编号合并；本机每20秒读取。KV跨区域有传播延迟，不将接单速度承诺为即时。
2. 本机代理持久记录请求与本地任务绑定；重启、丢失应答后先核对已有任务，不重新抓取。主队列仍是限频和执行状态的唯一权威。
3. 先发布公共来源阶段，再等待微博原调度器，随后发布最终阶段。只有完整上传并校验允许公开的文件后才切换版本指针；未成功同步的生成时间不作为线上发布成功。
4. 压缩文件使用内容哈希寻址，只允许既有网站公开资产；SQLite、Cookie、密码、原始日志、飞书发送历史等均不上传。禁止上传 Worker 替换线上代码。
5. 浏览器恢复轮询、自动加载新版本，保留领域；缓存传播时稍后重试，不把未看到的版本标成已加载。更新进度保留来源失败/暂停状态。
6. 后台离线会排队；未接单的请求1小时后过期，防止开机突然执行隔夜请求。电脑关机/未联网时无法实时抓取，原有唤醒保障保持不变。

KV 不用于高频事务：不用 list 轮询，空闲心跳5分钟；变化进度最短30秒写一次；仅新增/过期的公共文件上传。代理每日 UTC 硬上限750次写入（含失败尝试），给控制请求保留额度；达到上限停止发布并保留旧页面。动态快照保留两天、压缩资产三天，内容哈希上传记录一天后续期。它们不是新闻留存清理策略，不改本机每月清理安排。云端静态部署的生成时间更新时优先采用新静态版本，避免旧动态覆盖。

## 运维与验证

- `tools/refresh_cloud_setup.py`：默认只读核对固定站点、绑定与存储权限；`--apply` 才创建专用 KV 和 Secrets，不修改付费计划。
- `tools/refresh_cloud_agent.py --initialize`：首次生成本地私密凭据并写 GitHub Secrets；禁止覆盖已存在凭据。正常无参数运行出站代理；`--once` 单次健康检查。
- `tools/com.newshot.online-refresh.plist.example`：独立 KeepAlive LaunchAgent；原采集服务不用重启。
- `tools/test_refresh_cloud.mjs`：管理员认证、CSRF、重复提交、代理认证、发布白名单、完整版本切换。
- `tools/test_refresh_cloud_agent.py`：复用任务、应答丢失恢复、写预算持久化、初次连接不采集。
- 回滚只需停止出站代理；线上继续读取现有页面，原本机队列与飞书配置均不变。撤除云端绑定须在确认不再使用后单独执行，不能删除原数据或发送记录。
